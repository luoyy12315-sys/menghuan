## 一、现状盘点（改前）

### 1.1 完整层级（19 个叶子项，最深 4 层）

```
tab4「我的」
├─ 人设管理
├─ 基础档案          ← 性质上是设置，却在一级卡
├─ AI 图库           ← 同上
├─ AI 提示词← 同上（v0.45 从设置页搬上来的）
└─ 设置
   ├─ API 配置              → 对话模型 / 生图模型（两段混一页）
   ├─ 语音                              ← 唯一有实质收纳的一页
   │  ├─ 语音合成  → 选服务商 → 填四字段（3 层 + 弹窗）
   │  ├─ 识别模型  → 下载源 / 下载 / 删模型
   │  ├─ 音色        → 预置 / 克隆 / 手填 ID
   │  ├─ AI 主动打电话 → 每人设一条规则（可展开）

   │  └─ 接听延迟（裸数字输入框）

   ├─ 通知与提醒
   │  ├─ 任务到点提醒 / 手机操作通知 / 人设主动关心（三个开关）
   │  └─ 定时主动消息 → 选人设 → 填指令 → 联网搜索
   ├─ 数据与隐私
   ├─ 权限
   └─ 关于
```

### 1.2 四个具体问题

| # | 问题 | 证据 |
|---|---|---|
| 1 | **分组不清晰** | `SettingsScreen.kt:82-100`：7 个入口 `items` 列表平铺，**无任何小标题**。「API 配置」与「关于」是同一种 `NeuSheetRow`，视觉权重完全一致。 |
| 2 | **层级过深且不均** | 最深 4 层（设置→语音→语音合成→添加接入→选服务商弹窗）；最浅 1 层（设置→外观，内含 3 个胶囊）。深度差由"历史加页顺序"决定，不由内容量决定。 |
| 3 | **项排列无序** | `SettingsScreens.kt:330-406` 语音页：合成能力（语音合成/音色）、识别能力（识别模型）、主动行为（AI 主动打电话）、通话体验（铃声/接听延迟）**四类混装**。`接听延迟` 是裸 `NeuTextField` 夹在行卡中间，无归属标题。`AI 主动打电话` 本质是闹钟+通知能力，却挂在语音页。 |
| 4 | **缺少搜索/归类** | 19 个叶子项、0 个搜索入口。`AI 提示词`/`基础档案`/`AI 图库` 三项被提到「我的」页做一级卡（v0.45.0 的临时决定），**设置域被打散在两个页面**。 |

## 二、重构方案

### 2.1 核心决策

1. **一级分 4 组**（AI 与模型 / 语音与通话 / 提醒与通知 / 数据与系统），组标题带一句职责说明。
2. **取消「语音」中转层** —— 5 个子项直接上提到「语音与通话」组，最深层数 4 → 2。
3. **收回三项**：`AI 提示词` / `基础档案` / `AI 图库` 回到设置域；「我的」页只留 `人设管理` + `设置`。
4. **浅页合并**：`外观` 只有 3 个胶囊，就地平铺在「数据与系统」组里，不再单独占一页。
5. **加搜索框**：输入即过滤全部 4 组的行卡，标题与副标题都参与匹配。
6. **开关就地显示**：通知类开关不再点进二级页才看得到当前状态。

### 2.2 新分组与条目

#### ① AI 与模型 —— "喂给模型的东西"
| 条目 | 形态 | 说明 |
|---|---|---|
| 对话模型 | 独立页 | 从「API 配置」拆出（原来和生图挤在一页） |
| 生图模型 | 独立页 | 同上 |
| AI 提示词 | 独立页 | **从「我的」收回**；手风琴八段保持不变 |
| 基础档案 | 独立页 | **从「我的」收回** |

副标题一律报实时状态：对话模型报"当前：<名称>"，生图报"已配置/未配置"。

#### ② 语音与通话 —— 组内再分两小类
*能力（可离线/可配置）*
| 条目 | 形态 | 说明 |
|---|---|---|
| 语音合成 | 独立页 | 三家卡片，逻辑不动 |
| 识别模型 | 独立页 | 228MB 下载，逻辑不动 |
| 音色 | 独立页 | 预置/克隆/手填，逻辑不动 |

*通话行为*
| 条目 | 形态 | 说明 |
|---|---|---|
| AI 主动打电话 | 独立页 | **从语音页搬来**；每人设一条规则 |
| 语音通话铃声 | 独立页 | 铃声 + **接听延迟**合并进来 |
| 定时主动消息 | 独立页 | 从「通知与提醒」搬来（它本质也是"到点主动发"） |

> **「接听延迟」的处置**：现在是一个裸数字框夹在行卡中间。改成 `语音通话铃声` 页里的
> 一个独立小节「接听延迟」，带说明文字，语义归属明确。

#### ③ 提醒与通知 —— 开关全部就地
| 条目 | 形态 | 说明 |
|---|---|---|
| 任务到点提醒 | **就地开关** | 不再点进页才知道状态 |
| 手机操作进度通知 | **就地开关** | |
| 人设主动关心 | **就地开关** | |
| 联网搜索 Key | **就地开关** | 从「定时主动消息」页提到这里（聊天页联网也要用它，放这里是共同依赖） |

#### ④ 数据与系统 —— 低频
| 条目 | 形态 | 说明 |
|---|---|---|
| 外观 | **就地三胶囊** | 合并原来的独立页 |
| 权限 | 独立页 | 缺项时组标题旁挂红点 |
| AI 图库 | 独立页 | **从「我的」收回** |
| 数据与隐私 | 独立页 | 危险操作单独一段，保持现状 |
| 关于 | 独立页 | 版本 + 崩溃记录 |

### 2.3 导航与折叠交互

- **分组标题 = 手风琴**：常驻可点，箭头指示展开态；默认全展开（每组 ≤4 项，展开也不长）。
- **展开状态 `rememberSaveable`**：进页保持用户上次的选择。
- **搜索时无视折叠**：一输入就把命中项全展开，空输入恢复原折叠态。
- **二级页跳转一律走 push 转场**（沿用 `PUSH_TRANSITION_MS`），**返回栈深度 ≤ 2**。
- **子页顶部不再放返回以外的按钮**；「克隆音色」「ID」这类页内动作留在页内。
- **不在设置里再做弹层叠弹层**（`SettingsPage` 类注释里已写明这条动机）。
- 「恢复默认」只在 `customized == true` 时出现（沿用提示词页既有约定）。

### 2.5 影响与风险

| 风险 | 等级 | 处置 |
|---|---|---|
| 手册 12 处路径措辞不同步 → 助手答错"xx 在哪" | **高** | 手册与代码同版本改，`AiPromptsTest` 双向断言兜住；`replace` 全部追加在**链尾** |
| 老用户肌肉记忆：入口位置变了 | 中 | 组标题 + 副标题保留原关键词（"识别模型""语音合成"字样不动），搜索框可直达 |
| `VOICE` / `APPEARANCE` / `NOTIFICATIONS` 路由被删，通话页的 `onOpenSettings` 跳转要改 | 中 | 通话页现在跳 `ASR_MODEL` / `TTS_CONFIG`，这两个**保留**，只改 `SettingsScreen` 内的引用 |
| 折叠状态丢失 | 低 | `rememberSaveable` |
| 一级页变长（从 7 行到 ~16 行） | 低 | 4 个手风琴组 + 搜索，可控 |

### 2.6 建议的实施顺序

1. 先做**纯新增**：`SettingsGroup` 折叠组件 + 设置页搜索框（不动任何旧页）。
2. 再做**归组**：4 个组的内容从旧页搬进主页，路由先保留不动（双入口并存一版）。
3. 最后**删旧路由** + 改手册 + 改测试断言 + bump 版本。

拆三步的理由：第 1 步零风险可独立验收；第 2 步出问题还能退回旧页；第 3 步是纯删除，删错了立刻能看出来。

## 五、拍板结论（用户 2026-10-05 逐条确认）

| 问题 | 用户的原话 | 结论 |
|---|---|---|
| 重构范围 | 「全量重构」 | 四组 + 搜索 + 三个页面全删 + 「AI 提示词」收回 |
| 三项归属 | 「留人设管理和AI图库」 | 「我的」页留**人设管理 / 基础档案 / AI 图库**；只有「AI 提示词」进设置 |
| 分组要不要折叠 | 「我说的是设置里面的卡片，点进去就是全屏显示」 | **组标题只是视觉标签，不可点、不折叠**；卡片点进去照旧是全屏页 |

第三条一度被我误解成"要手风琴折叠"，用户直接点掉了那个术语。**教训：给用户看交互方案时
先画出来再说，不要先抛"手风琴""折叠"这类实现词**——用户脑子里的画面是"卡片点进去"，
我脑子里的关键词是控件类型名，两边对不上就会各说各话。

### 实施中踩到的四个坑（都记在这，下次别再犯）

1. **`replace` 目标串必须是"最终形态"**：v0.53.4 那条已经把「AI 图库」展开成长句，
   我再拿`"AI 图库、AI 提示词、设置。"` 去替换必然失配 —— 静默落空、不报错。
2. **短目标串只命中多处中的一处**：`"设置 → 语音 → 识别模型"` 在正文出现两次
   （一次带「我的 → 」前缀），只写短的那条会漏掉另一处。**要么带上前缀区分，要么写全。**
3. **被包含的同款 replace 是死代码**：先写`"设置 → 语音 → 「音色」卡片…"`（不含前缀），
   它已经把带「我的 → 」那句一起吃掉了；再写一条带前缀的**永远落空**。
   写第二条时看不出来，只会觉得"我明明写了怎么没生效"。
4. **`neuSurface(intensity = 0f)` 不是"透明底"**：它把 `color` 按 intensity 乘 alpha，
   0f = **整条全透明**。要"凹陷灰槽"得用 `inset = true`（平涂 `NeuTrack`、无描边）。
   搜索框写错的话会只剩一个光标飘在那儿。

### 验证方式（未跑构建的前提下怎么保证手册没写错）

写了一个**离线模拟器**：从 `AiPrompts.kt` 源码里解析出底稿 + 全部 69 条 replace，
按 Kotlin 语义（`trimIndent` 去首尾空行、只作用于紧邻字面量、`\` 转义、字符串内的 `//`
不算注释）在 Python 里重放一遍，检查命中数与残留串。

模拟器本身也踩了两个坑，值得记：
- **`.trimIndent()` 我按 14 字符切，实际 13** —— 一差一位就整段匹配不上；
- **去注释时没保护字符串字面量**，把 `https://open.bochaai.com` 里的 `//` 当成注释起点，
  后半条链全解析歪了。

**最终结果：69 条全部命中、9 类旧路径零残留、4 个新分组名全部到位、新增 20 条测试断言
逐条对着模拟产物核对通过。** 编译与真机仍待用户验证。
