## v0.64.0 · Live2D 动作系统（用户点名"先优化通话页 UI，再做完整套动作系统，做完出包"）

### 用户当场的三个决定（拍板原话，别再翻案）
1. **视频通话页布局**：不是 A/B/C 里任何一个，而是"**下面那块 UI 都不见、好像是移到了右边，顶栏的 UI 还要**"。
   → 落地为：默认上下分区（角色区 + 对话台），**右滑**把对话台整块横移出场进"纯净态"、
   **左滑**唤回，**顶栏（状态胶囊 + 计时）在纯净态里保留**。语音通话（无形象）不启用该手势。
2. 点击互动第一阶段：**只做默认行为 + 预留结构**（不给出配置界面）。
3. 新建动作编辑器：**只做普通模式**（参数级高级模式不做）。
4. 角色空间背景：**底色 + 4 张内置渐变 + 相册图片**（不做视频背景）。

### 视频通话页（`ui/realtime/RealtimeCallScreen.kt`）
- **上下分区、结构上不遮挡角色**：角色由投影完整收进上方那块，下方是「对话台」（页面底色）+ 静音/挂断。
  引擎新增 `CallVisualEngine.setViewportBottomInset(fraction)`；`Live2dCharacter.fitProjection` 多带
  `bottomInset / offsetX / offsetY`，`inset=0` 时**逐字退化成原实现**（所以语音通话那条路没变）。
  `VideoVisualEngine.applyCoverTransform` 同样按可用高度算 cover。
- 于是**不需要任何蒙版**（延续 v0.61.1 删暗色蒙层），字幕用正常灰阶就清晰。**别再往回调蒙版**。
- 字幕窗口从「一屏 6 行」收敛成 **3 行**（`CallSubtitleViewportHeight = 96.dp`）。
- **画面层尺寸恒定**：分区只改投影/矩阵，**不改视图尺寸** —— 否则右滑那 320ms 里 GL 表面反复重设，
  滑动时画面会抖（v0.60 那轮的同类坑）。
- 纯净态进度用 `Animatable` **跟手**（`snapTo(spread + dragAmount/width)`），松手弹簧归位；
  手势挂在 `BoxWithConstraints` **自己的 modifier** 上 —— 所以 `spread`/`scope` 必须声明在
  `BoxWithConstraints` **之外**（里面声明的状态那个 lambda 读不到），屏宽改用 `PointerInputScope.size`。
- 右滑进纯净态时底部 inset 同步动画到 0（`snapshotFlow { spread.value }` 推给引擎），角色随之铺满。

### 新的动作引擎（新包 `com.menghuan.app.live2d`，与通话解耦）
- **通用通道**：`GenericChannel`（`GENERIC_HEAD_X` 这类 id），加载模型时探测映射到该模型真有的参数。
  参数候选表里**同时列了老式 `PARAM_ANGLE_X` 命名**。归一化语义：`1.0 = 参数可用范围的 60%`
  （`ActionPlayer.AMPLITUDE_SPAN`），所以换模型不会被甩到破图。
- **舞台通道**（`GENERIC_STAGE_X/Y/ROT/SCALE`）走**渲染矩阵、零参数依赖** ——
  这是「翻跟斗任何模型都演得出来」的实现方式；`STAGE_ROT` 1.0 = 180°，翻一圈写 2.0。
- **播放顺序（别挪）**：`model.saveParameters()` 之后写入动作 → 再 `updateScheduler.onLateUpdate`
  （眨眼/呼吸/口型/物理）。所以**口型永远归实时语音**（lipSync 是加法叠加），
  且物理会跟着动作的身体角度甩。内置动作**一律不碰 `GENERIC_MOUTH`**（碰了角色会一直张着嘴）。
- **能力降级**：缺通道不崩、跳过缺的、`amplitudeScale` 压到 0.55~1.0；required 全缺才判不能跑（回退）。
- `Live2dCharacter` 新增：`playAction/stopAction/playExpression/hitRegion`、`capability`、`catalog`
  （模型的 `Motions`/`Expressions` 清单，GL 线程回调 `onCatalogReady`，回调里**只许转手**，不许碰 Room）。
- **死代码已清**：`requestState` / `groupFor` / `THINK|SPEAK|LISTEN_GROUP` 那一整条链已删
  （模型自己的 Idle 动作仍在底下跑，动作是叠在它上面的一层）。
- `Live2dStage` 接口（`realtime/visual/Live2dStage.kt`）：角色空间需要、通话不需要的那一组能力
  （inset / 拖动位移 / hit / 任意动作 / 能力表 / 清单回调）。`Live2dVisualEngine` 两个接口都实现。

### 联网搜索的根因（别再判成"用户 Key 填错了"）
- `search_key_enc/plain` 是**博查与 Tavily 共用的一把**：切服务商时输入框显示的是同一串、
  保存也写回同一串 → 拿博查的 Key 去打 Tavily 永远"没搜到"，读起来就是"切换没生效"。
  **与 v0.52.0 语音合成是同一个坑**，修法照搬 AGENTS §零.4「每家一套独立配置」。
- ⚠️ `saveSearchConfig` 三件事必须**同一个 edit 块、顺序不许换**：
  ① 老单桶**先落到它那一家的桶**（先清老键 = 把用户填过的 Key 凭空抹掉，v0.52.0 就是这么丢的）
  → ② 只写当前这一家 → ③ 最后才切 `search_provider`（先切再搬，老数据会记到新选那一家名下）。
- ⚠️ **第二条真故障，适用于所有"保存即返回"的设置页**：原来 `scope.launch { 写库 }` 之后**立刻**
  `onBack()`，而 `rememberCoroutineScope` 挂在这一页的组合上 —— 页面一拆，正在写 DataStore 的协程
  就被取消，表现正是"点了保存、切回来还是原来那一家"。现在 **await 写完再返回**。
- 删掉的老入口：`setSearchProvider` / `setSearchApiKey` / `setSearchCustomApiKey` / `setSearchCustomUrl`
  （少一条混写路径就少一次串味）。自定义家的老键名 `search_custom_key_*` 本来就等于新的分桶拼法
  （`search_<家>_key_enc/plain`、`search_<家>_url`），所以**三家对齐、零迁移**。
- 老单桶的虚拟归属：只在"这家整桶从没写过"时回退（`contains` 而不是判空 —— 主动清空写的是空串，
  键在=写过，不能被老键复活）；任何一次保存都会先搬进桶再清老键。
- 回归：`SettingsRepositoryTest` 加 3 条（三家各一份 / 清空一家不碰另外两家 / 老键归属并活过"保存别家"）。

### 视频通话背景（v0.66.0）

  `filesDir/call_background/<personaId>/<原图名>`，一张就够、换图先删旧的、**沿用用户那张图的原名**。
  库里不存绝对路径（同 [CallVisualStore] 的口径）。
